# Развёртывание и обслуживание

Подробные требования, однострочная команда установки и сценарии PostgreSQL описаны в [README](../README.md). `install.sh` поддерживает Debian, Ubuntu и Astra Linux с APT и systemd. Он использует **уже работающий** PostgreSQL, локальный или удалённый: создаёт на нём роль и БД с административными правами либо подключает существующую БД. Сервер PostgreSQL установщик не устанавливает.

При первой установке меню предлагает сетевой HTTP по IP, HTTPS с готовым сертификатом или только локальный HTTP. Для повторного изменения IP, порта, режима и БД выполните `sudo bash /opt/avt/install.sh`, пункт 2. Для нового пароля существующего пользователя — пункт 3. Пароли, заданные установщиком, выводятся один раз в терминал и не сохраняются в отдельный файл. `.env` содержит пароль роли PostgreSQL и должен оставаться доступен только служебной учётной записи и root.

Waitress слушает `127.0.0.1:8001`, Nginx — выбранный внешний порт. В сетевых режимах Nginx слушает `0.0.0.0`; в локальном режиме — `127.0.0.1`. Если сайт открывается на сервере, но недоступен извне, проверьте правила хостового и внешнего сетевых экранов (например, Azure NSG), а также правильность IP. HTTP допустим только в доверенной сети, так как пароли передаются без TLS. Для публичного доступа используйте HTTPS.

```bash
sudo systemctl status avt
sudo journalctl -u avt -n 100 --no-pager
sudo nginx -t
sudo ss -ltnp
curl http://127.0.0.1:8080/health/ready/
```

Используйте фактический порт и протокол вместо `8080`/HTTP. При HTTPS проверьте также сертификат. Проверка Django `manage.py check --database default` запускается установщиком. `check --deploy` в HTTP-режиме по замыслу Django предупреждает об отсутствии HSTS, SSL redirect и secure-cookie; включение их при HTTP делает авторизацию недоступной. Подробнее: [проверки Django](https://docs.djangoproject.com/en/5.2/ref/checks/).

Импорт тестовых данных выполняется только в пустую прикладную БД. Файлы `database_import/` содержат данные из тестовой PostgreSQL без действующих паролей. При установке с импортом пользователям выдаются случайные пароли Argon2id, выведенные в терминал. Для уже существующей БД исходные пароли недоступны — используйте меню сброса. Команда `database_import/import.sh` подходит для ручного импорта после миграций и до создания пользователей.

Резервные копии доступны администратору в интерфейсе: SQL для просмотра и скачивания, `.dump` для восстановления. Перед обновлением и сменой базы сохраните отдельную копию вне сервера. Изменение конфигурации при ошибке возвращает прежние `.env` и Nginx; миграции, уже применённые к выбранной БД, не откатываются. Повторный запуск установщика не удаляет старые БД и пользователей.

Для обновления кода используйте команды в [README](../README.md). Перед промышленным вводом проверьте установку и восстановление копии на целевом Linux-сервере.

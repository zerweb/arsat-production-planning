# АРСАТ — планирование и диспетчеризация производства

## Описание

Веб-приложение для ведения портфеля заказов и технологической подготовки производства. Оно объединяет изделия, заказы, маршруты обработки, производственные программы, задания, материалы и учёт выполнения в одной базе PostgreSQL. Серверная часть написана на Django; существующий интерфейс предприятия сохранён.

Проект разрабатывается по техническим заданиям на планирование заказов и автоматизацию технологической подготовки производства. Реализованные функции и оставшиеся ограничения описаны в [сопоставлении с ТЗ](docs/requirements-audit.md).

## Основные возможности

| Раздел | Что делает |
| --- | --- |
| Заказы и изделия | Состав заказа, чертежи, количество, сроки, приоритеты, статусы и история изменений |
| Технологические процессы | Связанные с изделием операции, рабочие центры, оборудование, время на партию и на одну деталь |
| Планирование | Годовая и квартальная программа, планы А и Б, расчёт загрузки |
| Производство | Производственные задания, выпуск, контроль качества и отклонения |
| Материалы | Потребность, остатки, дефицит и импорт файлов CSV/JSON/XLSX |
| Документы ЕСТД | Черновая маршрутная карта PDF по структуре ГОСТ 3.1118-82 |
| Администрирование | Роли пользователей, проверка PostgreSQL, SQL-копии и восстановление из `.dump` |
| Отчёты | Просмотр и выгрузка отчётов в XLSX/PDF |

Прямые интеграции с 1С, NX CAM и станками ЧПУ пока находятся в разработке и скрыты в интерфейсе. Маршрутная карта не заменяет утверждённый комплект документации ЕСТД.

## Сервер для установки

| Среда | Статус |
| --- | --- |
| Debian, Ubuntu, Astra Linux с APT и systemd | Установщик рассчитан на эту среду; полный прогон на целевом сервере ещё не проведён |
| Windows | Локальный экземпляр приложения работает, Bash-установщик для Windows не предназначен |

Для первого развёртывания рекомендуются следующие ресурсы; фактическая потребность зависит от объёма данных и числа сотрудников.

| Компонент | Рекомендация |
| --- | --- |
| CPU | 2 ядра |
| RAM | 4 ГБ |
| Диск | 10 ГБ свободного места плюс место для резервных копий |
| Сеть | Доступ к GitHub и пакетному репозиторию на время установки |
| Права | `sudo`, терминал, установленный `curl` |

Синтаксис сценариев, миграции и приложение проверены; для первого запуска нужен PostgreSQL на сервере либо реквизиты существующей БД.

## Установка одной командой

На новом сервере выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/zerweb/arsat-production-planning/main/bootstrap.sh | sudo bash
```

`bootstrap.sh` установит Git, загрузит [репозиторий проекта](https://github.com/zerweb/arsat-production-planning) в `/opt/avt` и запустит `install.sh`. Скрипт работает интерактивно: на вопросы о порте и базе данных нужно ответить в терминале. Если `/opt/avt` уже существует, загрузчик остановится, сохранив его содержимое.

Вариант без загрузчика:

```bash
git clone https://github.com/zerweb/arsat-production-planning.git /opt/avt && sudo bash /opt/avt/install.sh
```

## Настройка во время установки

### Адрес сайта

Укажите порт сайта от 1 до 65535; по умолчанию используется **8080**. Внутренний сервер Django слушает `127.0.0.1:8001`, поэтому порт 8001 для сайта выбрать нельзя.

Затем выберите режим доступа:

1. **Только на сервере:** Nginx слушает `127.0.0.1`. Сайт доступен по адресу `http://127.0.0.1:8080/` с самого сервера.
2. **По сети:** укажите домен или IP, а также готовые TLS-сертификат и закрытый ключ. Nginx слушает сеть по HTTPS. Без сертификата сетевой режим не включается.

IP сервера можно посмотреть командой `hostname -I`. Для доступа сотрудников убедитесь, что выбранный порт разрешён сетевыми правилами и сертификат соответствует имени сайта.

### PostgreSQL

Установщик предлагает два режима:

| Режим | Необходимые сведения | Действие |
| --- | --- | --- |
| Создать локальную БД | Название БД и нового пользователя | Устанавливает PostgreSQL, создаёт роль и БД, генерирует пароль |
| Подключить существующую БД | Host, port, database, user, password | Проверяет подключение и применяет миграции; существующую БД не удаляет |

В локальном режиме адрес PostgreSQL — `127.0.0.1:5432`. Реквизиты приложения записываются в защищённый `.env`, который исключён из Git. Для внешнего PostgreSQL база и пользователь уже должны существовать и иметь права на создание таблиц в выбранной базе.

### Тестовые данные

На вопрос об импорте можно ответить `y` или `n`; значение по умолчанию — **`n`**. При выборе `y` установщик использует файлы `database_import/01_roles_users.json` и `database_import/02_sample_data.json`: три тестовых заказа, изделия, маршруты и связанные справочники из подготовленной PostgreSQL.

Импорт разрешён **только в пустую базу** и выполняется одной транзакцией. Тестовые учётные записи отключены, пригодных паролей в фикстурах нет. При обычной установке достаточно ответить `y`. Отдельный Bash-скрипт предназначен для ручной подготовки чистой БД **после миграций и до создания администратора**:

```bash
cd /opt/avt && sudo -u www-data bash database_import/import.sh
```

Если администратор уже создан, база больше не считается пустой: повторный импорт намеренно завершится с ошибкой. Для обычной эксплуатации тестовые данные не требуются.

## Что выполняет установщик

1. Устанавливает системные пакеты и создаёт Python-окружение `.venv`.
2. Устанавливает версии зависимостей из `requirements.lock.txt`.
3. Настраивает подключение PostgreSQL и применяет миграции Django.
4. При выборе пользователя загружает тестовые фикстуры.
5. Создаёт первого администратора со случайным паролем, если действующего администратора ещё нет.
6. Собирает статические файлы, создаёт службу `avt` и конфигурацию Nginx.
7. Запускает приложение. Внутренним сервером служит Waitress под контролем управляющего процесса.

Установщик не использует заранее известные пароли и не перезаписывает существующий `.env`.

## После установки

Установщик выводит адрес сайта и путь к первому паролю администратора:

```text
/root/avt-initial-admin.txt
```

Файл доступен только `root`. Посмотрите его через `sudo`, войдите как `admin`, смените пароль и удалите временный файл. Если в подключённой БД уже есть действующий суперпользователь, его пароль не меняется.

Через раздел администрирования можно проверить подключение к PostgreSQL, управлять пользователями и создавать резервные копии. SQL-копии доступны для скачивания; восстановление через интерфейс принимает архив `.dump` и создаёт страховочную копию перед заменой базы.

## Расположение проекта

```text
/opt/avt/
├── bootstrap.sh                  # загрузка из GitHub
├── install.sh                    # установка сервера и приложения
├── manage.py                     # команды Django
├── config/                       # настройки и маршруты проекта
├── production/                   # модели, представления, API, миграции, тесты
├── database_import/             # фикстуры и Bash-импорт
├── templates/                   # HTML-шаблоны, включая исходный интерфейс
├── static/                      # CSS, JavaScript и логотип
├── tools/serve.py                # управление веб-процессом и восстановлением
└── docs/                         # архитектура, ТЗ и аудит безопасности
```

Локальные `.env`, `.runtime/`, `.backups/`, `.venv/` и `staticfiles/` исключены из Git. Файлы БД и резервные копии не размещайте в публичном каталоге веб-сервера.

## Проверка работы

```bash
sudo systemctl status avt
sudo journalctl -u avt -f
sudo nginx -t
curl -H 'X-Forwarded-Proto: https' http://127.0.0.1:8001/health/ready/
```

Проверка `/health/ready/` должна вернуть `{"ok": true}`. Журнал Django находится в `.runtime/app.log`. Если служба не запустилась, смотрите `journalctl -u avt -n 100 --no-pager` и результат `sudo nginx -t`.

## Обновление

Перед обновлением создайте и сохраните отдельную копию БД. Затем в каталоге проекта:

```bash
cd /opt/avt
sudo git pull --ff-only
sudo .venv/bin/python -m pip install -r requirements.lock.txt
sudo .venv/bin/python manage.py migrate --noinput
sudo .venv/bin/python manage.py collectstatic --noinput
sudo chown -R www-data:www-data .runtime .backups
sudo find staticfiles -type d -exec chmod 755 {} +
sudo find staticfiles -type f -exec chmod 644 {} +
sudo systemctl restart avt
```

`bootstrap.sh` предназначен для **первой** установки, не для обновления. Импорт тестовых данных не запускается повторно при обновлении.

## Удаление

Перед удалением сохраните резервную копию PostgreSQL и архив нужных файлов из `.backups/`. Остановите службу командой `sudo systemctl disable --now avt` и отключите конфигурацию сайта в Nginx. Каталог проекта и базу данных удаляйте отдельно после проверки копии: установщик намеренно не содержит команды для их автоматического удаления.
